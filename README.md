# PokemonMove

Android 向けの、DS・3DS作品のポケモンをまとめて管理するアプリ。
C# / .NET MAUI と PKHeX.Core を使用します。

## 現在の機能（0.11.0）

- D・P・Pt・HGSS・BW・BW2 の通常セーブとXY・ORAS・サンムーンの復号済みmainを Android のファイル選択から読み込む
- 主人公名・作品名・手持ち・第4世代18ボックス／第5世代24ボックス／XY・ORAS31ボックス／サンムーン32ボックス（各30枠）を表示
- ポケモンの日本語名・ニックネーム・レベル・タイプ・技・色違いを表示
- 非対応形式、主人公・手持ち・ボックス領域のチェックサム不一致を拒否
- 表示しない追加領域だけの不一致は、警告を表示して読み取りを継続

- バックアップ後に選択した個体をセーブから取り除き、バンクへ移動
- 同世代内の移動と第4→第5世代・第5→第6・第6→第7世代の一方向移動に対応し、ボックス空き枠へ引き出し、書き込み照合後にバンクから削除
- 再起動後もバンク一覧・詳細を表示し、名前で検索
- 移動の中断記録と復旧、バンク／移動前セーブのバックアップ書き出し

- 全国図鑑802種類の所持状況を登録済みの全セーブとバンクから集計
- 通常色／色違い、所持／未所持の切り替えと名前・図鑑番号検索

自動的なクラウド送信は行いません。USUM以降の作品とバーチャルコンソール作品は未対応です。

## 対応作品と作品間移動

DS版ダイヤモンド・パール・プラチナ・ハートゴールド・ソウルシルバー・ブラック・ホワイト・ブラック2・ホワイト2、および3DS版X・Y・オメガルビー・アルファサファイア・サン・ムーンに対応します。通常セーブ（512 KiB）とDraStic／DeSmuMEのDSVを選択できます。ステートセーブ、USUM、バーチャルコンソール作品、Switch作品は対象外です。
セーブ形式だけではダイヤモンドとパールを確実に区別できないため、作品名は「ダイヤモンド・パール」と表示します。BW・BW2は4作品を区別します。

同じバンクを経由して、第4世代内・第5世代内・XY・ORAS間・サンムーン間で移動できます。バックアップ・元セーブからの除去・書き込み後の照合・バンクからの除去・中断復旧は共通です。同世代内はポケモンの保存データをそのまま保持します。ゲーム内図鑑の捕獲フラグは更新せず、アプリ内の収集図鑑で集計します。BW・BW2・XY・ORAS・サンムーンへの引き出しはゲーム内で開放済みのボックスに限ります。
移動先に存在しないフォルムや持ち物は拒否し、バンクに残します。例：DPへのロトムの追加フォルム・はっきんだま、BWへのれいじゅうフォルム・かくごのすがた。合体中のキュレムは合体相手の保護のため、先にゲーム内で分離してください。メールを持つ個体も元のゲーム内で外してください。

XYとORASの間でも、個体データは変換せず移動します。ORAS専用のフォルム・持ち物・技・思い出せる技・特性をXYへ書き込むことは拒否し、個体はバンクに残します。自動でフォルムを戻したり、技や持ち物を削除したりはしません。対応するORASのセーブへ引き出してください。

### 第4世代→第5世代

第4世代の個体をバンクに移し、引き出し先にBW・BW2を選ぶと、最終確認画面で第5世代への変換を確認します。**第5世代から第4世代には戻せません。** 古い種類のポケモンでも、第5世代の保存形式になった個体は戻せません。

- PID・親ID・個体値・努力値・性格・色違いを保持し、名前の文字コードを変換します。
- 出会った場所・レベル・日付を移動情報に変更し、なつき度を70、技のPPを回復状態にします。ヌケニンなどの性別情報を補正する場合も確認画面で案内します。
- タマゴ・ギザみみピチューは世代移動できません。持ち物、変換で削除対象になるひでん技、変換時に変化するフォルムは、先に第4世代のゲーム内で外す・忘れさせる・通常に戻す必要があります。アプリが自動で持ち物や技を削除することはありません。
- 移動日は中断記録に保存し、後日の復旧でも同じ変換結果を再現します。移動先の書き込み確認後に元のバンク記録を消費し、旧バックアップからの再取り込みを抑止します。

第4世代は作品ごとに選択された主人公・手持ち／ボックスブロックを検証し、その有効ブロックを編集します。第5世代は主セーブの全ブロックのCRCとチェックサム表を照合し、変更した手持ち／ボックスとチェックサム表だけを書き換えます。破損を自動修復せず、バックアップ領域・未使用領域・DSV末尾を保持します。
生成データで第4世代内25通り、第5世代内16通り、第4→第5世代20通り、XY・ORAS間16通り、第5世代→XY・ORASの16通りの移動を確認しています。Azaharで実際のXY・ORASセーブを使った動作確認はこれからです。

### XY・ORASのmainとAzahar

Azaharの対象作品のセーブフォルダーにある、復号済みの `main` を選択します。XYは415232バイト、ORASは483328バイトです。暗号化された3DSカートリッジ全体のセーブ・ステートセーブ・ORAS体験版のmainは対象外です。
一般的な保存位置はAzaharのユーザーフォルダー内の `sdmc/Nintendo 3DS/<ID0>/<ID1>/title/00040000/<作品ID>/data/00000001/main` です。作品IDはXが `00055d00`、Yが `00055e00`、オメガルビーが `0011c400`、アルファサファイアが `0011c500` です。ユーザーフォルダーの実際の場所は端末の設定により異なります。

**Azaharを終了してから、実際にゲームが使用するmainを選んでください。** コピーだけを書き換えるとエミュレータ側の元ファイルには個体が残ります。Androidの制限で元ファイルを選択できない場合は、Azaharのユーザーフォルダーをファイル選択からアクセス可能な場所に設定してから利用してください。

全ブロックのCRCとメタデータを検証し、変更する手持ち／ボックスとそのCRCだけを書き換えます。撮影画像・無関係な領域・セキュアタイムスタンプを保持します。未対応フォルム・戦闘専用フォルム・合体中のキュレム・トリミング状態のトリミアンは、通常の姿へ戻してから移動してください。ゲーム内図鑑の捕獲フラグは変更しません。
移動前のmainバックアップを書き出して戻す場合は、ファイル名を `main` に戻してからゲームの保存先に置き換えてください。

### 第5世代→XY・ORAS

BW・BW2からバンクへ保管した個体を選び、XY・ORASへ引き出す際の最終確認で「第6世代へ移動」を選びます。**第6世代へ変換した個体はDS作品へ戻せません。** 第4世代からXY・ORASへは、先にBW・BW2を経由してください。

- 個体値・性格・親ID・色違い状態を保持します。色違い判定の仕様変更で色違いになってしまう個体はPIDを補正し、元のPIDを暗号化定数に保持します。
- 努力値が252を超える能力は第6世代の上限252へ調整し、確認画面で案内します。
- 出会った場所・日付は第5世代の情報を保持します。名前・リボン・なつき度・特性・PP・タイプや能力値の扱いは第6世代に合わせます。移動先のトレーナー・地域・思い出情報を設定します。
- タマゴ、持ち物がある個体、合体中のキュレムは先にゲーム内で準備してください。持ち物を自動削除しません。
- 変換時のランダム値や直前に開いたセーブの影響を排除し、移動先の変更前データから同じ結果を再現します。中断時も書き込みを確認してからバンクを消費します。

### サン・ムーン

Azaharのサン・ムーンの保存フォルダーにある復号済み `main`（441856バイト）を選択します。通常版のサン・ムーンが対象で、USUM・体験版・暗号化されたカートリッジ全体のセーブは未対応です。Azaharを終了し、コピーではなくゲームが実際に使うmainを選んでください。

32ボックス・すごいとっくんの能力値補正・出身作品に合った親ID表示に対応します。バトルチームに登録した個体／枠や、ポケリゾート内に同じ個体がいる場合は移動を止めます。先にゲーム内で戻す・登録を解除してください。ボックスと手持ちだけが収集図鑑のセーブ側の集計対象です。
全ブロックのCRCとメタデータ、チェックサム表の署名を検証します。編集は対象ブロックとCRC・署名に限り、バトルチーム・リゾート・ポケファインダー・セキュアタイムスタンプなどを保持します。署名のRSA整数は先頭ゼロも含め固定長で扱い、書き込み後の署名を再検証します。破損した入力は自動修復しません。

XY・ORASの個体を引き出す際に「第7世代へ移動」を選ぶと、一方向の変換を行います。**第7世代へ移した個体は以前の作品へ戻せません。DS作品からは先にXY・ORASを経由してください。**
親ID・個体値・努力値・性格・色違い・出会った情報を保持し、マーキング・特性・なつき度・思い出・リフレ関連の情報・PPなどを第7世代に合わせます。すごいとっくんは未実施として初期化し、移動先のトレーナーを設定します。タマゴ・持ち物がある個体・合体中や戦闘専用の姿は先に元のゲーム内で準備してください。

生成データでサンムーン間4通り、第6世代→サンムーン8通り、署名生成・既知署名と先頭ゼロを含む1024パターン・中断復旧を確認しています。Azaharで実際のサンムーンセーブを使った動作は未確認です。

### バンク形式の互換性

バンクは世代情報（`pk4` / `pk5` / `pk6` / `pk7`）を明示するバージョン5へ移行します。第4・5世代は同じ136バイト、第6・7世代は同じ232バイトですが、形式を長さだけから推測しません。
旧バージョン1〜4を互換読み込みし、移動済み履歴・引き出し権限・中断記録を保持します。旧コピーの引き出し権限を勝手に付与しません。新版のバンクは旧アプリでは読み込めないため、更新前のバックアップを外部に保管してください。

## 2画面端末（RGDS / AYN Thor向け）

初期設定では、2画面を検出すると自動で下画面を操作・上画面を表示に割り当てます。1画面の端末では通常表示を続けます。保存済みの割り当てと明示的な停止設定は保持します。

1. 割り当ての変更・再開・停止は、ホーム右上のメニューから「2画面設定」を開きます。
2. 操作用の下画面と表示用の上画面を選び、「2画面モードを開始」を押します。通常は画面1が操作、画面0が表示です。
3. 上下が逆なら設定で入れ替えて開始してください。操作画面の切り替え時はホームへ戻るため、必要ならセーブを開き直してください。
4. 手持ち・ボックス・バンクで個体をタップすると上画面の画像・能力値が更新されます。実際の移動は下画面の専用ボタンを押して確認します。
5. 図鑑の行を選ぶと、上画面は代表画像と所持状況を表示します（個体の能力値とは区別します）。

画像は通常色・色違いの静止画を1604枚同梱し、通信なしで表示します。フォルム・性別差分は代表画像で、3D表示は未実装です。
上画面は表示専用で、名前・レベル・タイプ・性格・特性・もちもの・6能力値・努力値・個体値・何Vか・親のID・技を表示します。タマゴはタマゴ表示です。
努力値は6能力ごとと合計、個体値は6能力ごとと31の能力数（○V）を表示します。親のIDは元の作品の表示方式に合わせ、第7世代出身は6桁、以前の作品出身は5桁で表示します。すごいとっくんの能力値補正に対応し、V数は元の個体値31の能力数を表示します。
能力値は元の個体を変更せず、コピーから計算します。手持ちは現在HPも表示し、ボックス・バンクは最大HPを表示します。

Android標準の独立ディスプレイとActivity起動APIを使用し、上画面の表示は専用の操作不可Activityで行います。
アプリを離れると上画面を閉じ、復帰時に再表示します。設定は保存されます。画面が1つ、取り外し、移動拒否の場合は通常画面で操作できます。
一つの論理画面を折り曲げるだけの端末には、この独立2画面モードは対応していません。
実際のRGDS・Thorの表示順やActivity移動は実機での確認が必要です。画面IDの割当・選択状態の自動テストとAndroidビルドを検証しています。

## 収集図鑑

セーブを開くと図鑑の集計対象として自動登録します。SSを開いた後にHGを開いても、両方の登録が保持されます。
登録はアプリの再起動後も残り、図鑑の「更新」では**登録したすべてのセーブを実ファイルから読み直して、バンクと合算**します。
引き出し先として読み込んだセーブも登録します。登録が0件の場合はバンクのみを集計します。

ホームの「登録セーブを管理」で追加・再接続・登録解除ができます。解除は集計対象から外すだけで、セーブやバンクの個体は削除しません。
移動・削除・権限切れなどで読めない登録がある場合は集計を止め、その登録を保持したまま再接続または解除を案内します。
過去の所持履歴を累積する方式や、読めないファイルの古い所持状況を使い続ける方式ではありません。

v0.4.0以前に開いたファイルの登録一覧は保存されていません。更新後にSS/HGをそれぞれ一度開いて登録してください。
現時点の読み込み対応はD・P・Pt・HGSS・BW・BW2・XY・ORAS・サンムーンです。異なる作品も同じ登録一覧に保持し、すべてのセーブとバンクを集計します。登録情報の形式キーはDPが`dp`、Ptが`pt`、HGSSが`hgss`、BWが`bw`、BW2が`b2w2`、XYが`xy`、ORASが`oras`、サンムーンが`sm`です。登録一覧の保存形式は維持し、バンクの旧形式は互換読み込みします。

サンムーンまでの全国図鑑 No.001–802 が対象です。同種を複数持っていても、種類数は1です。
通常色と色違いの種類数は独立に表示し、フォルム違いは共通の種類として集計します。
タマゴは孵化するまで除外し、検証できない個体は含めません。
バンクには旧版のコピー保管も含みますが、図鑑表示で引き出し権限を変えることはありません。

名前検索はひらがな・カタカナ・半角カナに対応し、全国図鑑番号（例：001、152）でも検索できます。
行を選ぶと、手持ち・ボックス・バンクそれぞれの所持数と、セーブ別の内訳を確認できます。
ゲーム内の「見つけた／捕まえた」フラグとは別の、現在の所持図鑑です。セーブやバンクへ書き込みません。

「更新」で再読込できます。中断した移動がある場合は、先にバンク画面で復旧してください。集計中にバンクの内容が変わった場合も、不整合な数を表示せず再更新を案内します。
読めないセーブ・バンクを勝手に未所持として扱わず、エラーを表示します。

### 登録一覧の保存と移行

登録一覧はアプリ専用領域の `saves/registered-saves.json` に保存します。実ファイルの参照・作品・トレーナー・形式キーを記録し、ポケモンやセーブ本体のコピーは含めません。
同じ参照を再度開いたときは重複登録せず更新します。登録上限は100件です。

「登録セーブを管理」の「一覧を書き出す／取り込む」で移行できます。**アプリ削除前にはバンクと登録一覧をそれぞれ外部へ書き出してください。**
登録一覧にセーブ本体は含まれません。再インストールや端末変更後はAndroidの権限を取り直すため、一覧取り込み後に各ファイルを「接続し直す」で選択してください。

## 移動の使い方

1. **エミュレータを終了し、実際に使用するセーブを選択**します。選択したファイルを書き換えます。別のコピーを選べば、エミュレータ側の原本は変わりません。
2. 手持ち／ボックスから個体を選び「バンクへ移動」を確定します。移動前のセーブを保存し、削除後の書き込みを再読込・照合してからバンクの保管を確定します。
3. バンクで個体を選び「セーブへ移動」。引き出し先のセーブ・ボックスを指定し、確認します。**保管元への引き出しも可能**です。
4. 引き出しは空き枠のみ。書き込みを再読込・照合してからバンクから削除します。同じ個体データが引き出し先にあれば拒否します。

Android の OpenDocument で実ファイルへの読み書き権限を取得します。ファイル選択のキャッシュを書き換える方式は使いません。
端末内の通常セーブを使い、エミュレータと同時に編集しないでください。

### 旧版のコピー保管

v0.2.0 の保管データはコピーなので、**そのまま引き出せません**。元セーブに残っている同じ個体を「バンクへ移動」すると、その記録を移動済みへ切り替えます。
メール付き個体の移動と、戦える手持ちがなくなる操作には対応していません。

### 中断とバックアップ

- 外部セーブを変更する前に、セーブの移動前後の画像と操作をバンクに記録し、移動前ファイルを専用領域へ保存します。
- 中断中は新しい移動・バックアップ取り込みをロックします。バンク画面の「中断した移動を復旧する」で同じセーブを選び、状態を照合します。
- 書き込み済みなら保管状態を確定、未変更なら中止します。部分書き込み・不明な内容では勝手に上書きせず、明示確認後に移動前のセーブへ戻します。
- バンクはアプリ専用領域 `bank/bank.json` に保存します。引き出し済み記録のIDを残し、同じインストールで古いバンクバックアップを取り込んでも復活させません。
- 移動履歴を巻き戻す「直前の状態へ戻す」は廃止し、バックアップ取り込みは履歴を保ったマージにします。
- 「直前のセーブのバックアップを書き出す」は復旧用です。通常はアプリの中断復旧を使ってください。セーブだけを手動で巻き戻すとバンクと整合しなくなります。

**アプリ削除・端末変更の前に、中断中の移動を復旧し、バンクを外部へ書き出してください。** 共有先で保存を完了する必要があります。バックアップにはポケモン・トレーナー情報が含まれます。
開発版のデバッグ署名が変わると更新に旧版の削除が必要な場合があります。必ず削除前にバックアップしてください。

これは通常のアプリ操作での重複防止です。ユーザーが別途コピーしたセーブやアプリデータの巻き戻し、バックアップを別端末で並行使用する行為まで防ぐものではありません。

## セーブの選択

ゲーム内でレポートを書いた後、エミュレータを終了して実際に使う通常セーブを選択します。

- melonDS：512 KiB の `.sav`
- DraStic：バッテリーセーブの `.dsv`（通常セーブまたは DeSmuME フッター形式）
- ステートセーブ、ROM、圧縮ファイルには対応していません。

Android のファイル選択を利用するため、広範なストレージ権限は要求しません。
エミュレータの保存場所にアクセスできない場合、書き換え対象を確定できないため移動は行わないでください。
Android 実機での読み取りは DraStic / SS で確認済みですが、新しい書き込み・復旧画面の実機確認はこれからです。

## 構成

- `PokemonMove.Domain`：画面で扱う読み取り結果と解析インターフェース
- `PokemonMove.Engine`：PKHeX.Core を使った第4〜7世代の解析・検証・移動・一方向の世代変換
- `PokemonMove.Infrastructure`：ローカルバンク・原子的な保存・バックアップ
- `PokemonMove.App`：Android 用 MAUI 画面とファイル選択
- `PokemonMove.Engine.Tests`：生成した D/P/Pt/HG/SS/B/W/B2/W2/X/Y/OR/AS/SN/MN データ、DSV、破損・非対応データのテスト
